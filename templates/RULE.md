# App Deploy Common RULE (복사용)

> **사용법**: 이 파일을 새 프로젝트 루트에 `RULE.md`로 복사하거나, `.cursor/rules/`에 `.mdc`로 옮긴 뒤 frontmatter만 추가한다.  
> Cursor / Claude / Copilot 등 AI가 **비기능 요구사항·아키텍처·배포**를 일관되게 따르도록 하는 공통 기준이다.  
> 프로젝트 고유 기능(화면·도메인)은 이 파일이 아니라 기획/설계 문서에 둔다.

---

## 0. AI 행동 원칙

1. 이 RULE과 프로젝트 설계안이 충돌하면 **보안·결제·개인정보·스토어 정책**을 우선한다.
2. 비밀값(API Key, OAuth Secret, 서비스 계정 JSON)을 코드·커밋·채팅·로그에 넣지 않는다. `.env` / 시크릿 매니저만 사용한다.
3. “임시로 클라이언트에 키 넣기”, “영수증 검증 생략”, “RLS 끄기” 같은 우회를 제안·구현하지 않는다.
4. 구현 전 스택이 명시되지 않으면 아래 **기본 아키텍처**를 따른다.
5. 답변·코드는 프로젝트 언어 규칙(예: 한국어 UI 카피)을 따르고, 불필요한 대규모 리팩터를 하지 않는다.

### 0.1 질문 우선 (필수 — 추측 금지)

조금만 궁금하거나 애매하면 **추측·임의 결정하지 말고 사용자에게 먼저 묻는다.**  
기획 의도, UX 카피, 화면 분기, 라이브러리 선택, 폴더 구조, 스토어/광고/결제 콘솔 값, “이 정도면 충분한지”까지 **뭐든** 해당한다.  
사용자가 모른다고 하면 같이 선택지를 좁혀 고민한다. “나중에 바꾸면 됨”으로 조용히 고정하지 않는다.

물어본 뒤에도 당장 막히지 않는 작업(문서·마이그레이션 초안·페르소나 분리 등)은 병행해도 된다. 다만 **질문 답 없이는 되돌리기 비싼 결정**(패키지명 확정 외 구조 분기, 유료 API 호출, 실 AdMob/IAP 연동, 스키마 파괴적 변경)을 진행하지 않는다.

## 1. 기본 아키텍처 (템플릿)

```
[ Flutter Client (Android 우선, iOS 후속) ]
    │  Auth / IAP / AdMob / 로컬 캐시 / 만세력(클라이언트 연산)
    ▼
[ Backend BaaS: Supabase ]
    │  Auth(OAuth) + PostgreSQL + RLS + Edge Functions
    ▼
[ 외부 API ]
    - LLM: Gemini (서버리스 프록시만 호출, Dual-Key/429 폴백)
    - 결제: Google Play Billing (서버 영수증 검증)
    - 광고: AdMob (배너 / 리워드 / 네이티브)
```

| 계층 | 역할 | 금지 |
|------|------|------|
| Flutter | UI, 선택형 UX, IAP 트리거, 광고 표시, 클라이언트 만세력 | LLM API Key, Play 결제 신뢰 단독 처리 |
| Supabase DB | 유저·지갑·히스토리·결제 로그, RLS | 서비스롤 키를 앱에 노출 |
| Edge Functions | LLM 프록시, 재화 차감, IAP 검증, 일일 지급 | 클라이언트 신뢰만으로 재화 증가 |

**스택 고정(앱 배포 템플릿)**  
- 클라이언트: Flutter  
- BaaS: Supabase (Auth + Postgres + Edge Functions)  
- LLM 호출: Edge Function 경유만  
- 결제: **인앱결제(IAP)만** (외부 웹결제·우회 링크 금지 — 스토어 정책)  
- 광고: Google AdMob (`google_mobile_ads`)

## 2. 보안 (필수)

### 2.1 시크릿
- Gemini / OAuth Client Secret / Play 서비스 계정 키 → **서버(Edge Function secrets / CI secrets)** 만.
- 앱에는 Supabase **anon key** + 프로젝트 URL만. `service_role` 금지.
- 모든 설정값은 `.env` / `--dart-define` / 시크릿에 명시하고, 샘플은 `.env.example`만 커밋.

### 2.2 인증·인가
- OAuth(1차: Google + Kakao 권장, 네이버는 공수 여유 시).
- DB는 **Row Level Security** 기본 ON. `auth.uid() = user_id` 패턴.
- 재화 차감·지급·패스 활성화는 **Edge Function + DB 트랜잭션**에서만.

### 2.3 개인정보 vs 민감정보
- **일반 개인정보**(이름, 생년월일, 성별, 연락 채널 등): 서비스 목적상 필요 시 DB 저장 가능. 목적 최소화, 동의/처리방침, RLS, 탈퇴 시 삭제.
- **민감정보**(건강·질병, 생체인식, 사상·신념, 성생활, 범죄경력 등): DB·로그·분석에 **저장 금지**. 불가피하면 별도 법적 근거·동의·최소화를 설계안에 명시하기 전에는 구현하지 않음.
- 앱 삭제/캐시 삭제 시 로컬 데이터 유실 가능성은 UX에 고지.

### 2.4 LLM
- 프롬프트·페르소나 `.md`는 **서버(Edge/Storage)** 쪽에 두고 앱 재배포 없이 수정 가능하게.
- 클라이언트가 보낸 입력을 그대로 신뢰하지 않음(카테고리·턴 수·재화 잔액은 서버 재검증).
- 추가 질문 컨텍스트는 **슬라이딩 윈도우**(요약 1 + 직전 1턴 + 신규 질문)로 토큰 상한 유지.

## 3. 결제 (인앱결제)

1. 소비성(부적/쌀알)·기간권(패스) 모두 **Play Billing / App Store IAP**만 사용.
2. 클라이언트 `purchase` 성공 ≠ 재화 지급. **Edge Function이 purchaseToken 검증 후** 지급.
3. purchaseToken **중복 사용 방지** 테이블 필수. 환불/취소 웹훅 또는 정기 조회 시 재화·패스 회수 로직 설계.
4. 가격·상품 ID는 스토어 콘솔과 코드/`products` 설정을 일치. 하드코딩 금액 문자열은 UI 표시용만.
5. 결제·지급 최소 이력(주문ID, 상품ID, 상태, uid, 시각)을 DB에 남겨 품질·분쟁 대응.

---

## 4. 광고 (AdMob)

1. 개발/디버그: **테스트 광고 단위 또는 testDevices**만. 실광고 클릭 금지(계정 정지 리스크).
2. 권장 배치: 하단 배너 / 보상형(리워드) / 생성 중 **네이티브**. 결과 대기 중 **강제 전면 닫기 UX**는 지양.
3. 리워드 미로드 시 화면 정지 금지 → 토스트 후 재시도.
4. 패스 유저: 배너·전면 숨김 가능, **자발적 리워드**는 유지 가능(설계안 따름).
5. 광고 단위 ID는 env/설정으로 분리. 실 ID를 문서에만 두고 코드 기본값은 테스트 ID.

---

## 5. UX 비기능 (사용성)

1. **선택형 UI 우선**(생년월일·MBTI·카테고리 등). 직접 입력은 최후 수단.
2. 프로필 저장/불러오기, 목록 추가·삭제가 쉬울 것. 큰 터치 영역·높은 대비(어르신 사용 고려).
3. LLM 대기: 로딩 애니메이션 + 짧은 안내 문구. 응답 후 결과와 광고가 자연스럽게 이어지게.
4. 어려운 용어는 탭 시 짧은 설명(언더라인/툴팁).
5. 점술·사주 결과 화면·설정에 **오락 목적 면책** 문구 필수.

---

## 6. 데이터·품질

1. LLM 질문/답변·카테고리·모델·토큰/에러는 **품질용으로 DB 기록**(민감정보 제외).
2. 과거 결과 재열람은 저장된 원문으로 하고, 불필요한 재호출 금지.
3. 일일 무료 재화·광고 시청 한도는 서버 기준일(KST)로 판정. 클라이언트 시계만 신뢰 금지.
4. 회원 탈퇴: 계정·서버 저장 데이터 삭제(또는 익명화) 경로를 설정에 제공.

## 7. 환경변수·설정 목록 (프로젝트에서 채움)

```
ADMOB_BANNER_ID=
ADMOB_REWARD_ID=
ADMOB_NATIVE_ID=
OAUTH_GOOGLE_...=
OAUTH_KAKAO_...=
```

## 8. 스토어·법령·운영

1. 개인정보 처리방침 **공개 URL** 필수(노션/GitHub Pages 등). 앱 내에는 요약 + 공식 법령 링크 + 문의 메일.
2. 이용약관: 공정위 전자상거래 표준약관 준수 고지.
3. OAuth 사용 시 **계정 탈퇴** 필수.
4. Play 개인 개발자: 비공개 테스트 기간·테스터 수 요건 충족 후 프로덕션.
5. AdMob/IAP/앱 서명 키는 백업·권한 최소화.
6. Supabase Free: 7일 무활동 Pause 방지용 일 1회 ping(CI cron) 권장.

---

## 9. 배포·CI (Android 우선)

1. 패키지명·앱명·문의 메일은 설계안/스토어 콘솔과 단일 출처로 맞춤.
2. 릴리즈: 서명 키 스토어는 CI 시크릿. 디버그 키로 스토어 업로드 금지.
3. 파이프라인: 빌드 → 내부/비공개 테스트 트랙 → 프로덕션.
4. 스크린샷·스토어 설명·데이터 안전성 양식을 출시 체크리스트에 포함.

---

## 10. 메서드 파이프라인 (LLM 기능 앱)

```
입력(선택형) → 클라이언트 만세력(필요 시) → 부적 차감(서버)
  → 페르소나.md + 프롬프트 → Gemini(JSON) → 결과 저장·표시
추가질문: 쌀알 차감 → (요약+직전1턴+질문) → Gemini → chats 저장
```

- 페르소나/시스템 프롬프트는 기능별 `.md`로 분리 관리.
- 모델 기본: Gemini Flash 계열. 키는 free → 429 시 paid 폴백(운영자가 시크릿으로 전환).
